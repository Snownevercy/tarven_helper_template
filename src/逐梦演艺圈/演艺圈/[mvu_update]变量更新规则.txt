---
变量更新规则:
  叙事.${标题|引言}:
    check:
      - [强制更新] 绝不省略！每轮回复必须重新生成。
      - [标题] 紧扣当前剧情焦点的冲击性短语 (禁章节号)。
      - [引言] <20字哲理短句，契合当前氛围。

  世界.当前时间:
    format: YYYY-MM-DD 周X HH:mm
    check:
      - 随剧情流逝推进(如:过夜+1天, 对话+10分)，严禁倒流

  世界.当前地点:
    format: 国家-城市-具体位置-天气
    check:
      - 移动/转场时更新，必须输出完整的地点格式链（如：中国-北京-三里屯-小雨），严禁省略。

  世界.${时代新闻|行业新闻}:
    check:
      - [格式] 必须带时间戳，例: "[MM-DD] 新闻内容"。
      - [触发-剧情] 当剧情发生重大社会影响事件时，强制更新对应新闻。
      - [触发-历史] 若无剧情事件，且旧新闻已超时(时代>10天 / 行业>5天)，检索真实历史填补。
      - [限制] 时代新闻=全球大事件; 行业新闻=娱乐圈热点。严禁捏造/超时未更新。

  剧情.备忘录:
    type: |-
      { [事件: string]: string } # Value: 触发时间(YYYY-MM-DD) 或 触发条件
    check:
      - [写入限制] 仅收录以 User 为主体且跨度>3天的长线伏笔(如: 颁奖/分红)。key必须为纯描述性事件名，严禁加入任何额外编号/系统标识符。
      - [双向确认] 涉及双边博弈的条件(如: 合同/对赌/邀约)，必须在 User 明确同意(签字/口头答应)后方可写入；严禁记录 NPC 单方面抛出的未决议筹码。
      - [禁区] 严禁记录短线琐事(如: 吃饭/跑腿)。
      - [清理机制] 每轮强制扫描：IF 本轮已触发 / 已在剧情中完成闭环(事件结算/明确放弃) / 时间点超时失效 -> 强制 Remove。仅保留逻辑未闭环项。

  主角.${姓名|性别|国籍}:
    check:
      - 性别开场锁定。姓名/国籍仅在实质变更(如: 正式改名/艺名取代本名/移民)时更新。

  主角.外貌:
    check:
      - 仅记录肉体持久性改变(如: 毁容/整容/衰老)，严禁描写衣着/妆容等。

  主角.生日:
    format: YYYY-MM-DD
    check: 开场锁定。

  主角.年龄:
    type: number
    check: 依据 [世界.当前时间] - [主角.生日] 自动重算周岁。

  主角.职业:
    check: 实时同步User职业，支持多重兼职(如: 学生/演员)。

  主角.资本:
    type: number
    check:
      - 仅计算现金流(存款+手持)。严禁计入不动产/合同估值。
      - [格式] 必须纯数字(如 50000)，严禁单位(万/亿)或逗号。统一折算为人民币元。

  代表作品.${影视作品|音乐作品|综艺作品}:
    type: |-
      { [作品名: string]: string } # Value: 状态/关键数据
    check:
      - 收录 User 核心参与(导/演/编/唱/投资)作品，未得到准确作品名前严禁收录。
      - 随剧情推演状态 (筹备->拍摄->上映->完结)。
      - [数据锚定] 作品进入上映/播出/发行阶段后，value必须附带已产生的关键数据，用/分隔:
        * 影视: 状态/票房或播放量/评分(如: 已完结/票房12.6亿/豆瓣7.2)
        * 音乐: 状态/销量或播放量/评分(如: 已完结/销量52万张/豆瓣8.1)
        * 综艺: 状态/收视率或播放量(如: 播出中/平均收视1.2%)
      - [未产生数据] 筹备中/拍摄中阶段无数据，维持纯状态词即可。
      - [数据一致性] 数据一经写入，后续剧情引用(谈判/咖位评估/媒体报道)必须与此处一致，严禁前后矛盾。

  代表作品.获取奖项:
    type: |-
      { [奖项名: string]: string } # Value: 获奖年份/备注
    check: 仅记录 User 已获得的真实奖项。

  专业评估.当前咖位:
    check:
      - 核心算法: 综合 [粉丝基础] + [代表作品] 质量进行加权计算。
      - 等级锚点: 素人 -> 十八线 -> 三线 -> 二线 -> 一线 -> 顶流 -> 巨星。

  专业评估.${业务能力|媒体风向|社会风评|粉丝基础}:
    check:
      - [触发] 各方对User本人的评价，作品发布/才艺展示/隐私曝光/社会活动时更新。
      - [定义] 媒体风向 = 官方/主流态度 ; 社会风评 = 大众口碑。
      - [限制] 严禁使用形容词、比喻句、情绪词与主观渲染，每个变量值控制在 15 字以内。

  价值分析.签约公司:
    check:
      - 当User签约/解约/开办/入股全代理契约经纪公司时更新。
      - 对User其余公司状态变更情况保持无视。

  价值分析.合约状态:
    type: string[]
    check:
      - 概括核心契约 (如: 经纪约10年/项目协议/对赌协议/核心代言)。
      - 用户输入明确的签约/解约/续约时更新。

  价值分析.投资项目:
    type: |-
      { [项目名: string]: string } # Value: 盈利状况/持仓详情/投资金额
    check:
      - User商业投资行为，新增/撤资/分红/盈亏状况变化时更新。

  价值分析.广告代言:
    type: |-
      { [项目名: string]: string } # Value: 时长/渠道
    check:
      - User商业代言广告，签约/续约时更新，到期/解约即删除。

  人脉.社交版图:
    type: string[]
    check:
      - 概括User核心社交圈层 (如：京圈/学院派）。
      - 变更时强制移除冲突/同义的标签。

  人脉.关系簿:
    type: |-
      { [NPC姓名: string]: number } # Value: -100~100
    check:
      - 数值 = NPC对User的单方面综合态度。增减仅看NPC主观视角：NPC从User处得偿所愿时+2~5，受挫时-2~5。初始为0，严禁单次交互暴涨。
      - [入库锁] 必须满足: 1.真实全姓名(张导/小王禁入); 2.现实社会影响力 或 与User存在持续利益/权力关系(单次出场的服务性NPC禁入，如路人/群演/服务员)。虚构NPC满足"持续利益/权力关系"条件的，允许入库。

  人脉.近期互动:
    type: string[]
    check:
      - [格式] ['NPC名(↑原因)', 'NPC名(↓原因)']
      - [逻辑] 打包记录本轮交互NPC。只允许 replace 指令替换整个旧数组。

  人脉.情人:
    type: |-
      { [姓名: string]: string } # Value: 关系阶段(炮友/热恋/冷战)
    check:
      - 仅收录实质肉体关系/正式恋人。暗恋/暧昧/嫖娼严禁入库。
      - 必须真实全名，关系破裂即 Remove。

  人脉.团队:
    type: |-
      { [姓名: string]: string } # Value: 职能与简述
    check:
      - 收录范围：User核心团队成员（经纪人/助理/公关/法务等持续雇佣关系）及User控制的公司签约艺人。单次项目合作者不入库。
      - Value格式："职能·一句话简述"（如："经纪人·人脉广，擅长商务谈判"/"签约艺人·新人，主攻偶像赛道"）。
      - 成员加入/离职/解约/职能变更时更新。离职或解约后强制Remove。
      - 与关系簿不互斥，团队成员同时在关系簿中维护好感度数值。

  蝴蝶效应.已抹除列表:
    type: |-
      { [被抢占作品: string]: string } # Value: 原作者名
    check:
      - 记录 User 抢占的未来作品。用于触发后续抹除机制。
